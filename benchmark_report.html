Key results

Each model reads invoice PDFs as page images and returns 15 structured fields (vendor, customer, totals, dates, references). The headline metric is end-to-end score: the share of all fields present in a document that the model extracted correctly.

Bottom line: Claude Fable 5.1 posts the highest end-to-end score (89.1%) and holds the top spot on the fair-subset re-score too — but that's on only 207 documents at $77.67/1k, a thin and expensive sample next to the rest of the field. Gemini 3.6 Flash remains the strongest production pick: a large, cheap run (2,323 docs, $10.04/1k) that trails the top score by just 0.2 points. Qwen 3.6 27B is still the best open-weight value at roughly a fifth of Gemini's cost with only 1.6 points less accuracy — its newer sibling Qwen 3.8 27B (86.8%) doesn't improve on it despite the version bump. Mistral Small 3.2 24B is the cheapest credible option tested at $0.39/1k for 83.0%. GPT-5.6 Terra is still the fastest model tested, and Claude Opus 5 still gives the most accurate individual answers (92.2%), but at 4–20× the unit cost of the mid-tier options it only makes sense for high-value documents.

What kind of failure is it?

Every ground-truth field across all model runs combined — ≈395,000 comparisons — split by outcome. The totals are almost never string-identical (ground truth stores raw numbers, models copy the printed format) but overwhelmingly correct after normalisation. Vendor name and the addresses are mostly a normalisation problem; PO number, delivery note and payment terms are a coverage problem — the model returns nothing at all.

Method & caveats

  • Setup. Invoice PDFs rendered locally to page images (up to 4 pages per document, 150 dpi) and sent to each model with the same extraction prompt and JSON schema, temperature 0, via OpenRouter — plus one Gemini 3.6 Flash deployment on GCP Vertex for comparison. Reasoning modes were capped at minimum effort so models are compared on extraction, not thinking-token budgets. Two endpoints (Qwen 3.8 Max, Claude Fable 5.1) make reasoning mandatory and reject it disabled outright — those two ran with reasoning forced on at minimum effort, everything else with reasoning off.
  • Ground truth. Model output is compared field-by-field against a reviewed ground-truth set, with tolerant matching for dates and number formats.
  • Document category is excluded from all scores. Every model scored ~0% on it because the ground truth uses internal labels (e.g. “Expense”) while models return the document’s printed type — a taxonomy mismatch to fix in the ground truth, not a model failure.
  • Unequal run sizes. Runs range from 207 documents (Claude Fable 5.1) to 4,973 (Ministral 14B) because of per-model cost caps. The fair-subset re-score on the 118 shared documents mostly confirms the ordering — Claude Fable 5.1 and Claude Opus 5 hold the top two spots either way — though Gemini 3.6 Flash drops from 2nd to 5th on the smaller sample while Qwen 3.6 27B and the GCP Gemini deployment move up into 3rd and 4th.
  • Vendor name scores understate the models. A large share of vendor-name misses are formatting variants of the correct name; tightening ground-truth normalization would lift every model roughly equally.
  • Failure types (in “What kind of failure is it?”): exact = string-identical to ground truth; formatting mismatch = same value after normalisation (date formats, thousand separators, accents, punctuation) — these count as correct in all scores; wrong value = returned but doesn’t match; not returned = null or absent. Pooled across all fourteen models’ runs.
  • Costs are actual billed OpenRouter charges at list prices, not estimates.
  • Meta Muse Spark 1.2 was not benchmarked. OpenRouter gates that endpoint behind an account-level 18+ age attestation that wasn't completed before this report was built, so every call returned HTTP 403 with zero data collected — it is omitted here rather than shown with a misleading 0% score.
